# AIOps Incident ETL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Validate the requested Azure ETL pipeline and its generated report; automated test-file changes are outside this scope.

**Goal:** Add a local command that reads recent `/simulate` request and `search_service` dependency telemetry from Azure Log Analytics, correlates it with Pandas, and writes the latest failed request as evidence-only JSON.

**Architecture:** `DefaultAzureCredential` authenticates a `LogsQueryClient` using the configured Azure identity. Two read-only queries retrieve requests and dependencies; Pandas left-joins by `OperationId`, computes the request-window summary before the join, and selects the latest failure. The report is written locally and its directory is git-ignored.

**Tech Stack:** Python 3.12, `azure-identity`, `azure-monitor-query`, Pandas, `uv`, Azure Log Analytics.

**Spec:** `docs/superpowers/specs/2026-10-11-aiops-incident-etl-design.md`

## Global Constraints

- Query the existing Azure Log Analytics workspace; do not provision Azure resources or call Microsoft Foundry.
- Read `/simulate` requests and `search_service` dependencies from the last 48 hours.
- Use two Azure queries and a Pandas left join on `OperationId`.
- Keep dependency fields null when a request has no matching dependency span.
- Write `data/incidents/latest.json` only after complete query results and successful transformation.
- Keep `data/incidents/` out of Git.
- Keep ETL packages in the local `etl` dependency group and leave Docker `requirements.txt` unchanged.
- Do not include injected-fault labels or expected root-cause labels in the report.

### Task 1: Implement the local incident extraction command

**Files:**
- Create: `etl/__init__.py`
- Create: `etl/extract_incidents.py`
- Modify: `.gitignore`
- Modify: `pyproject.toml`
- Modify: `uv.lock` (generated by `uv add`)
- Output at runtime: `data/incidents/latest.json` (ignored by Git)

**Interfaces:**
- `load_query_frame(client: LogsQueryClient, workspace_id: str, query: str) -> pd.DataFrame` executes one workspace query and returns its first result table; it rejects partial results.
- `build_incident_report(requests: pd.DataFrame, dependencies: pd.DataFrame) -> dict[str, object] | None` returns the evidence report for the newest failed request, or `None` when no failed request is present.
- `main() -> int` validates configuration, authenticates, runs both queries, writes JSON only when a report exists, prints the result path, and returns a process status.

- [ ] **Step 3: Define the two bounded workspace queries**

In `etl/extract_incidents.py`, define these queries and a shared 48-hour duration:

```python
REQUEST_QUERY = """
AppRequests
| where TimeGenerated > ago(48h)
| where Name contains "/simulate"
| project OperationId, TimeGenerated, ResultCode, DurationMs, Success, ItemCount
"""

DEPENDENCY_QUERY = """
AppDependencies
| where TimeGenerated > ago(48h)
| where Name contains "search_service"
| project OperationId, TimeGenerated, Name, DurationMs, Success
"""
```

Pass `timedelta(hours=48)` as the SDK `timespan` for each query as well. Convert the returned table rows with `pd.DataFrame(data=table.rows, columns=table.columns)`. If the response is a `LogsQueryPartialResult`, raise an error containing its partial error instead of using incomplete rows. Return an empty DataFrame with the expected columns if Azure returns no tables.

- [ ] **Step 4: Implement the Pandas join and evidence report**

Implement `build_incident_report` with this sequence:

```python
request_rows = requests.copy()
dependency_rows = dependencies.copy()
request_rows["TimeGenerated"] = pd.to_datetime(
    request_rows["TimeGenerated"], utc=True, errors="coerce"
)
request_rows["DurationMs"] = pd.to_numeric(
    request_rows["DurationMs"], errors="coerce"
)
request_rows["ResultCode"] = pd.to_numeric(
    request_rows["ResultCode"], errors="coerce"
)
```

Before joining, convert `ItemCount` to numeric and fill missing weights with `1`. Compute `total_requests` as the sum of `ItemCount`, `failed_requests` as the sum of `ItemCount` where `Success` is false, and `p95_latency_ms` as the 0.95 quantile of non-null request `DurationMs` values. Filter failed rows using `Success == False`. If there are none, return `None`. The p95 is computed from the returned duration samples; the FastAPI telemetry configuration currently uses a sampling ratio of `1.0`.

Drop dependency rows with a null `OperationId`, normalize remaining operation IDs to strings, then left-join requests to dependencies on `OperationId` with request and dependency columns renamed to distinguish their timestamps, durations, names, and success values. Sort failed joined rows by request timestamp and then dependency duration, with null dependency duration first; select the final row so the newest request wins and the longest dependency wins among spans for that request.

Return exactly these top-level fields: `operation_id`, `timestamp`, `request`, `dependency`, and `window_summary`. Put integer `status_code` and numeric `duration_ms` under `request`; put `name`, `duration_ms`, and nullable boolean `success` under `dependency`; put `total_requests`, `failed_requests`, and `p95_latency_ms` under `window_summary`. Convert Pandas/NumPy values to JSON-safe Python values and convert missing dependency values to `None`. Do not add fault or root-cause fields.
